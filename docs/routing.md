# Skill 分工与路由样例

三项 Skill 都是制作能力的专项入口，输入是可制作的双足角色及动作要求，输出是工程、导出物与观察证据。默认运行环境为可用的 Blender MCP 或本地 Blender；Meshy 只在资产准备阶段需要。Skill 不绑定某个 MCP 工具名，也不声明已经验证所有运行时。

| Skill | 主负责意图 | 可组合能力 | 相邻边界 |
| --- | --- | --- | --- |
| `character-body-mechanics` | 行走、转停、坐站的承重与平衡 | 表演负责情绪 | 手与道具关系由物体交互负责 |
| `character-prop-interaction` | 搬运、持握、工具命中 | 身体力学负责复杂脚步 | 无道具的情绪变化由表演负责 |
| `character-acting` | 注意力、反应、犹豫与情绪动作 | 身体力学维持步态 | 不负责面部绑定和口型 |

原有 `animated-character-pipeline` 覆盖从角色生产到引擎集成；本工程专项 Skill 提供动作制作知识。完整生产链可组合使用，明确动作任务由对应专项主负责。仅调用 Meshy、创建绑定或集成引擎，不因出现“角色动画”就加载全部三个 Skill。

`SKILL.md` 保留共同制作决策和完成依据；任务分支在直接链接的 `references/` 中。每个 ZIP 可独立解压，组合能力按名称选择，无跨包文件链接。新增脚本应来自反复出现的确定性操作，新增动作资产应来自已确认作品。

## 路由验收样例

以下是人工标注的预期选择，尚未做模型选择器实验，不表示路由准确率。

| 用户请求 | 预期主负责 | 可组合 |
| --- | --- | --- |
| 做一段有重量的走路、右转再停下 | 身体力学 | — |
| 用 Blender 做坐下和起立 | 身体力学 | — |
| 脚像在溜冰，膝盖每一步都跳，修这段动作 | 身体力学 | — |
| 角色坐得太低，起不来，重新设计发力动作 | 身体力学 | — |
| 双手搬起木箱放到桌上 | 物体交互 | 身体力学 |
| 斧头命中没力量，帮我重做挥斧动画 | 物体交互 | — |
| 他一转身手就离开箱子，改好持握和转身 | 物体交互 | 身体力学 |
| 听到身后声音，先警觉再转头 | 身体表演 | 身体力学 |
| 走得很累，但仍然想赶路 | 身体表演 | 身体力学 |
| 确认安全后松口气，别演得太夸张 | 身体表演 | — |
| 用 Meshy 生成并下载一个已绑定角色 | provider 或角色生产能力 | 不加载本组 |
| 给这个 Meshy 人物重新绑骨骼和刷权重 | 角色绑定能力 | 不加载本组 |
| 人物走路相关的游戏代码有 bug，修状态机 | 引擎实现能力 | 不加载本组 |
| 导出已有动画，不改动作内容 | 导出或集成能力 | 不加载本组 |
| 做人物眨眼和说话口型 | 面部动画能力 | 不加载本组 |
| 让四足狼警觉回头 | 四足动画能力 | 本组未覆盖 |
| 只替换角色材质，保留疲惫动画 | 材质能力 | 不加载本组 |
| 给斧头做 PBR 材质 | 材质能力 | 不加载本组 |
| 写一个动画失败后自动重试的 Agent harness | harness 开发 | 不加载本组 |
| 整理走路 case 的发布包与版本号 | 本工程开发工具 | 不加载本组 |

扩展前先增加对应实际制作 case，评估是否属于现有任务分支。只有输入、制作方法或交付物形成稳定边界时才新增 Skill。
